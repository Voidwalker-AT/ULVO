# ADR-001: Read-only foundation with explicit verification

Status: adopted for the initial partial prototype.

Windows remains primary, while the existing WSL Rust toolchain validates a Linux target. Do not install native Rust or infer Windows compatibility from Linux tests. Keep separate backend identities and reject execution where support is absent.

Use a four-crate workspace with deterministic serde domain models, std-based adapters, toml parsing, and clap CLI. These direct dependencies are justified by schema serialization, controlled manifest parsing, and consistent CLI validation. No service/database is needed.

Default inventory reads metadata only. Version probing is opt-in, bounded, and restricted to fixed argument pairs and conservative native installation roots. Configured paths are never executable instructions. Unknown architecture/vendor/ownership remain unknown. Project manifests express requests, not resolved dependencies.

Costs: incomplete Windows/multi-distribution coverage; unknown fields; conservative probe rejection; no OS-level subprocess sandbox. Completeness and security enforcement must be proven in subsequent milestones, not represented by polished output.

Writable Cargo home, target outputs and evidence remain inside the repository. Lock dependencies from crates.io. Preserve failure logs. Do not commit unrelated files or invent Git author identity.
